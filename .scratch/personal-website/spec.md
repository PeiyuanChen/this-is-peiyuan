# Spec：个人网站

Status: ready-for-agent

## Problem Statement

我希望有序记录自己的思想与生活，并给关心我的朋友一个了解我近况的窗口。目前我的文章散落在各处、十多年积累的摄影作品缺乏对外展示的地方。我需要一个属于自己的、长期可维护的个人网站：放成篇的文章、技术学习笔记和摄影作品集。建站与运维方式必须简单，内容必须便于编辑，且在十年尺度上依然可维护——我每年只写几篇到十几篇文章，不应为维护这个站点付出持续的额外精力。

## Solution

基于 Jekyll 的静态个人网站，托管在 GitHub Pages，通过 GitHub Actions 构建部署。网站设三个固定栏目：

- **随感**：面向读者的、完整成篇的非技术文章（生活、生命、工作、社会、历史、艺术的思考）。
- **笔记**：技术学习记录，分「读书技术笔记」与「专题学习笔记」两个子类。
- **摄影**：以相册为单位的作品集，相册主要按时期（如 2025）组织，特殊经历（一次旅行）独立成集。

站点以 Minimal Mistakes 主题为基底做轻度定制（中文排版、安静极简气质），摄影页内置 PhotoSwipe 全屏灯箱。照片由本地脚本从原片自动生成三档网页图并提取 EXIF，原片只存本地。图片位置通过配置解耦，未来可零改动切换到 COS/TOS。接入 Cloudflare Web Analytics 查看访问情况。

日常工作流：本地用 Markdown 写作、本地预览、`git push` 即发布。

## User Stories

### 访客（朋友）

1. 作为访客，我希望打开网站首页就看到作者的简短自我介绍和最近的文章与相册，以便快速感知他的近况。
2. 作为访客，我希望在手机上也能舒适地阅读文章和浏览照片，以便随时打开。
3. 作为访客，我希望文章排版适合中文长文阅读（字号、行距、留白），以便读几千上万字不累。
4. 作为访客，我希望文章中的少量图片与文字自然混排。
5. 作为访客，我希望通过清晰的导航在「随感 / 笔记 / 摄影」三个栏目间切换。
6. 作为访客，我希望看到随感栏目下所有文章按时间排列的列表，并能快速定位某年的文章。
7. 作为访客，我希望浏览笔记栏目时能区分「读书」与「专题」两类笔记。
8. 作为访客，我希望点开一篇文章时 URL 稳定可收藏、可转发给朋友。
9. 作为访客，我希望看到文章的发布日期。
10. 作为访客，我希望在文章末尾或侧边容易地找到作者的其他文章入口。
11. 作为访客，我希望在「关于」页了解作者是谁、他如何看待写作与摄影。
12. 作为访客，我希望在关于页找到作者的邮箱，以便在想深入交流时联系他。
13. 作为访客，我希望摄影栏目首页以封面网格看到所有相册及其年份，按时间倒序排列。
14. 作为访客，我希望点入一个相册后看到该相册的整组照片网格和相册的简短说明。
15. 作为访客，我希望点击相册中的任意照片进入全屏灯箱浏览，并能左右切换、按 ESC 或点遮罩退出。
16. 作为访客，我希望灯箱中看到清晰的大图（2000px），而不是被压缩的小图。
17. 作为访客，我希望在照片上直接看到光圈、快门、ISO（字号清晰可辨），以便了解拍摄参数。
18. 作为访客，我希望在作者提供说明时看到照片的 caption（位于照片下方或侧边），没有说明时画面保持干净。
19. 作为访客，我希望浏览相册时图片能懒加载、页面不会一次拉取几百张图片而卡顿。
20. 作为访客，我希望相册和照片页面在国内网络环境下可接受地打开（并在未来访问体验不佳时，作者能在不改变内容结构的情况下改善图片加载）。
21. 作为访客，我希望通过 RSS/Atom 订阅随感更新（可选增强）。

### 作者（我）

22. 作为作者，我希望用一条命令（或脚本）新建一篇带正确 front matter 和日期的文章草稿。
23. 作为作者，我希望用 Markdown 写作，不接触 HTML。
24. 作为作者，我希望本地一条命令启动预览，所见即所得。
25. 作为作者，我希望写完后 `git push` 即自动构建上线，不需要手动部署。
26. 作为作者，我希望构建失败时能在 GitHub 上清楚看到失败原因。
27. 作为作者，我希望创建一个相册时只需新建一个文件夹、放入原片、跑一次脚本，三档网页图、EXIF 和相册数据全部自动生成。
28. 作为作者，我希望脚本为相册生成/识别封面图，并允许我手动指定。
29. 作为作者，我希望照片按我在文件夹中的排列顺序（文件名排序）展示。
30. 作为作者，我希望为单张照片可选地填写 caption，且填写位置直观（与照片数据放在一起）。
31. 作为作者，我希望为相册填写标题、日期/年份和简短说明。
32. 作为作者，我希望批量导入初期的两三百张照片时，脚本可以稳定重复执行、已处理的内容不重复处理（增量/幂等）。
33. 作为作者，我希望脚本能跳过或报告无法读取 EXIF 的照片，而不是中断整批处理。
34. 作为作者，我希望原片永远留在本地，脚本只向仓库写入网页图，仓库体积可控、不需要 Git LFS。
35. 作为作者，我希望所有图片 URL 由统一配置前缀拼接，未来切换 COS/TOS 只改一行配置并跑同步脚本。
36. 作为作者，我希望 Cloudflare 统计脚本在本地预览时不触发，只在线上生效。
37. 作为作者，我希望在 Cloudflare 后台看到 PV、UV、访客地区、设备与来源、热门文章。
38. 作为作者，我希望未来购买域名后，只改少量配置即可绑定，且所有旧链接不失效。
39. 作为作者，我希望未来增加新栏目或新内容类型时，不需要重构现有结构。
40. 作为作者，我希望有一份 README，记录本地环境要求、写作/发布命令、照片处理流程和常见问题，以便多年后自己遗忘时能快速捡起来。
41. 作为作者，我希望站点结构和配置尽量简单朴素，降低十年后依赖失效、主题停更带来的维护风险。

## Implementation Decisions

### 总体技术栈与部署

- Jekyll 4.x，Ruby 3.3（本机已具备）；依赖通过 Bundler 锁定（Gemfile.lock 提交）。
- 主题：以 Minimal Mistakes 为基底（以 gem 或 vendored 方式引入，倾向 gem 引入 + 覆盖样式/布局，减少分叉维护；摄影布局在站点内自写）。
- 构建部署：GitHub Actions workflow，步骤为 检出 → Ruby setup → `bundle install` → `jekyll build` → 上传 Pages artifact → deploy；本地预览命令为 `bundle exec jekyll s`（注意本机 WindowsApps 下存在失效的 jekyll 占位程序，统一通过 `bundle exec` 调用）。
- 站点资源：随仓库走，图片先仓库托管；遵守 ADR-0001（Actions 构建）与 ADR-0002（图片位置解耦、不做 LFS、原片本地留存）。

### 信息架构与 URL

- 三个栏目用 Jekyll collections 实现：`essays`（随感）、`notes`（笔记）、`albums`（相册）。
- 永久链接：
  - 随感 `/essays/:year/:slug/`
  - 笔记 `/notes/:slug/`
  - 相册 `/photography/:slug/`（年度相册 slug 如 `2025`，旅行相册如 `kyoto-2019`）
- slug 一律英文或拼音；页面/导航显示中文栏目名。链接一经发布不再更改。
- 笔记通过 front matter 字段区分子类（读书 / 专题），笔记列表页按子类分组；读书笔记可记录书名。
- 导航：随感、笔记、摄影、关于；笔记在导航中位置弱于随感。

### 页面

- **首页**：简短自我介绍 + 混合最新流（最新随感与最新相册按日期合并、倒序，展示标题/日期/相册封面缩略）。
- **随感列表页**：按时间倒序，可按年分组；文章详情为中文长文排版，文内图片自然混排。
- **笔记列表页**：读书 / 专题分组。
- **摄影首页**：相册封面网格，封面 + 标题 + 年份，倒序。
- **相册页**：相册说明 + 照片网格（懒加载缩略图），点击进入 PhotoSwipe 灯箱。
- **关于页** `/about/`：自我介绍、写作与摄影简介、明文邮箱。
- 全站安静极简：文章区大量留白、易读；摄影区通过独立布局实现大图沉浸。需保证中文排版（中文字体栈、标点、行距）与移动端响应式。

### 照片展示与 EXIF/caption

- 灯箱：PhotoSwipe（借鉴 al-folio 的集成方式），支持左右切换、手势、键盘、ESC 退出，加载 2000px 大图。
- EXIF：脚本提取 光圈 / 快门 / ISO（以及相机、镜头，可留存但界面只要求展示前三项），在灯箱图片上以**有一定大小、清晰可读**的方式叠加展示（非极小字）。
- caption：每张照片可选；展示位置为照片下方或侧边（灯箱内布局实现）；无 caption 时不占位。不设地点字段，地点由作者自行写进 caption。

### 图片处理脚本

- 独立的本地脚本（Ruby 实现，与站点构建解耦，不依赖 GitHub 环境），输入：相册源文件夹（原片 + 作者元数据），输出：站点内的网页图目录与相册数据文件（供 Jekyll 读取的 front matter / data file）。
- 每张原片生成三档：缩略图、中等图、2000px 大图（JPEG 质量与单张体积控制在几百 KB 量级，具体参数在实现中标定）。
- 自动提取 EXIF；无法读取时跳过 EXIF 字段并在运行报告中提示，不中断批处理。
- 行为要求：幂等/增量（已处理且源文件未变的照片不重复生成）；照片顺序按文件名排序；封面可自动取首张并允许作者指定。
- 作者元数据（caption、封面指定、相册标题/年份/说明）以简单可手编的形式存放（如每张照片同名 sidecar 文件或相册清单文件），格式在实现中确定，原则是人类可直接编辑。
- 新建文章/相册的脚手架命令：生成带日期与正确 front matter 的文件模板。

### 图片位置解耦

- `_config.yml` 提供 `image_cdn`（默认空字符串）。所有照片 URL 在模板/数据中以「前缀 + 相对路径」构成。
- 未来切 COS/TOS：设置前缀 + 用对象存储 CLI（coscli / tosutil）对网页图目录做增量同步；不改动任何文章与相册数据。默认域名无需备案；自定义图片域名需 ICP 备案——切换时再处理。

### 统计

- Cloudflare Web Analytics：统计 beacon 仅在生产环境（配置项开关/JEKYLL_ENV=production）注入，本地预览不触发；站点编号放在 `_config.yml`。
- 可看到 PV/UV、地区、设备、来源、热门内容；不做"本文阅读 N 次"的页面计数器，不引入不蒜子。

### 显式不做

- 不做站内评论（联系走邮箱/微信）；如未来需要，加 Giscus。
- 不做用户账号、后台管理、服务端程序、数据库。
- 不做地图坐标、照片地点结构化字段。
- 不做照片水印（若未来需要再加）。

## Testing Decisions

好测试的标准：只验证外部行为与产物，不对模板内部实现细节、CSS 类名做断言。不追求高覆盖率，只覆盖真正有逻辑、易出错的部分。

1. **图片脚本单元测试（minitest，Ruby 自带，不引入新框架）**：使用一张固定的测试样片（带已知 EXIF），断言：生成三档图片且尺寸符合约束；EXIF 提取结果（光圈/快门/ISO）正确；重复运行不重复处理（幂等）；缺失 EXIF 的样片不导致失败并体现在报告中；输出的相册数据包含照片顺序与封面信息。
2. **整站构建冒烟测试**：在 CI（Actions）中用少量示例内容完成完整构建，断言：构建退出码为 0；首页、随感列表、笔记列表、摄影首页、关于页、示例相册页均生成；相册数据引用的每个图片路径在产物中真实存在；站内链接无死链（可用成熟的链接检查方式）。

视觉、排版、文章内容不做自动化测试，以本地预览与浏览器实际查看为准。

## Out of Scope

- 自定义域名购买、ICP 备案、自有服务器租用与运维（未来事项）。
- COS/TOS 的实际接入（仅完成位置解耦与文档预案）。
- 评论系统、阅读次数计数器、照片水印、付费/私密内容、多语言（i18n）。
- 初期两三百张历史照片之外的照片整理工作（站点只提供工具，照片的挑选与归档由作者在本地完成）。
- 将旧有其它平台（如历史社交平台）内容迁移进来。

## Further Notes

- 主要受众在国内，兼顾欧美访客；当前对 Pages + 仓库图片的国内速度先观察真实体验，再依据 ADR-0002 决定是否启用对象存储。
- 长期维护原则：依赖最小化、配置集中、内容（Markdown/图片）与机制（Jekyll/脚本/主题）分离；任何第三方服务（统计、图片托管）都以可替换的配置点接入。
- 仓库尚未初始化 git：实现开始时需 `git init`、创建 GitHub 仓库并启用 Pages（Actions 作为 source）；gh CLI 未安装，可用普通 git remote 方式完成，GitHub 端的仓库创建与 Pages 设置由作者在网页端操作（这是仅有人能完成的步骤，届时由实施流程给出具体指引）。
- README 需覆盖：环境准备（含 bundle exec 与 WindowsApps 占位问题说明）、写文章步骤、照片导入步骤、发布步骤、未来切域名/COS 的检查清单。
